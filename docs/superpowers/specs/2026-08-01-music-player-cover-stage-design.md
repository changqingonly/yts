# 音乐播放器封面舞台与主题色背景设计

## 背景

当前音乐页把完整方形封面缩放到黑胶中心的圆形标签中，生成图的主体、构图和色彩无法被识别。目标是参考用户提供的播放器布局：左侧完整封面，右侧歌曲信息/歌词区域，底部全宽进度与控制区；封面与页面背景使用同一张图的主题色融合。

## 目标

- 封面始终以 1:1 正方形呈现，完整展示生成图，不再把封面裁成黑胶中心标签。
- 左侧封面成为首屏主视觉，右侧保留歌曲元数据和歌词阅读区域。
- 背景色由当前封面自动提取，使用低饱和、低亮度衍生色，保证封面与舞台融合且文字对比度稳定。
- 保留现有播放、进度、切歌、循环、音量和封面生成/删除/重试事件契约。
- 生成 prompt 强调专辑封面构图质量，禁止模型生成黑胶、圆形标签、边框、UI 元素和乱码文字。

## 非目标

- 本次不新增歌词服务或逐行歌词时间轴。当前音乐播放数据没有逐行歌词字段，右栏只提供真实的“暂无歌词”状态；后续有数据契约后再接入滚动高亮。
- 不替换图片生成器的 PNG 返回契约，不把占位生成器伪装成真实模型。

## 视觉与布局

`MusicPage` 的播放器主舞台改成三段结构：

1. 主内容左右两列。左栏为方形封面、歌曲标题、艺人和封面操作；右栏为作者/作曲元信息和歌词阅读区域。
2. 主内容下方为全宽时间进度条。
3. 最底部为上一首、播放/暂停、下一首、音量、循环等现有控制。

封面容器使用稳定的 `aspect-ratio: 1 / 1` 和响应式最大尺寸；图片使用 `object-fit: cover`，不允许通过宽高分别缩放造成变形。黑胶不再包裹封面，只作为低对比的边缘装饰（或在窄屏隐藏），不得遮挡封面主体。

## 主题色提取与持久化

封面 PNG 生成完成后，在生成 worker 中按固定步长采样像素，忽略透明像素和接近纯黑/纯白的无效背景点；对采样颜色进行量化/聚类，选取权重最高的主题色。该流程参考 `xiong35/color-extraction` 的像素采样与主色聚合思路，具体实现保持服务端现有依赖边界，不让每次打开播放器的 mac 前端重复采样。

主题色与封面产物一起持久化，使用 `output_hash` 与 PNG 一一绑定；接口返回封面状态时同时返回原始主题色（RGB 或 HEX）。前端只读取该值并写入播放器舞台的 CSS 自定义属性，例如 `--cover-theme-rgb`；CSS 只用该颜色生成低饱和、低亮度背景层、光晕和阴影，不直接将高亮原色铺满页面。

历史上已生成但没有主题色的封面必须通过明确的一次性回填任务补齐：读取现有 PNG、计算并保存主题色；计算失败的封面标记为失败并暴露原因，不静默回退到固定主题色。新生成图片的主题色计算或持久化失败时，生成 job 不得进入 ready。

## Prompt 契约

`_cover_prompt` 继续使用歌曲标题和艺人作为语义输入，但输出约束改为：

- 1:1 square album artwork / 专辑封面设计；
- 单一明确视觉主体，占画布约 70–80%，前景、中景、背景层次清楚；
- 强化色彩、光线、材质和构图，使缩略图仍可识别；
- 标题/艺人只作为主题概念，不在画面中生成文字；
- 禁止黑胶唱片、圆形标签、唱片机、边框、水印、Logo、UI 模板、拼贴留白和乱码文字。

## 数据流与错误处理

封面状态变化时，页面先清理旧主题色和旧对象 URL，再读取接口返回的新主题色并更新舞台变量。当前歌曲切换、封面删除、重新生成和组件卸载都必须取消或失效旧请求，避免旧封面或旧颜色写回当前舞台。主题色缺失或服务端计算失败必须进入现有页面错误通道，不能掩盖问题。

## 测试

- 后端测试断言新的 prompt 包含 1:1、主体占比/层次和禁止黑胶/文字等约束。
- 前端静态布局测试断言正方形容器、右侧信息/歌词区域、底部进度控制结构存在，且不再依赖中心圆形封面作为主要展示。
- 主题色提取单元测试覆盖：多色图取稳定主题色、透明/无效像素被忽略、计算异常显式失败、同一 `output_hash` 不重复计算。
- 回填任务测试覆盖：无主题色的历史封面被补齐，计算失败的封面不会被标记为 ready。
- 前端测试断言主题色直接来自接口，不在播放器加载时创建 Canvas 重复计算。
- 运行现有音乐页生命周期与前端布局测试，确认播放事件契约未改变。
